# Plan 01-02: PostgreSQL Schema, Migrations & Row-Level Security

## Objective
Author complete, production-grade Supabase PostgreSQL schema with strict Row-Level Security (RLS) policies for CareLedger data isolation and audit logging.

## Tasks
1. Create `supabase/migrations/20261115_careledger_schema.sql`:
   - Enums: `user_role`, `relationship_status`, `medication_status`, `dose_status`, `alert_status`.
   - Tables: `profiles`, `care_relationships`, `medications`, `medication_schedules`, `dose_logs`, `appointments`, `caregiver_alerts`, `audit_logs`.
   - Triggers: Automatic `updated_at` timestamps, automated audit log generation.
2. Define Row-Level Security (RLS) policies:
   - Elders can view and update their own profiles, schedules, dose logs, and appointments.
   - Caregivers can view and manage profiles, schedules, and alerts ONLY for elders with active relationships.
   - Audit logs are insert-only / append-only.
3. Export TypeScript database definitions in `src/types/database.ts`.

## Acceptance Criteria
- SQL migration file is syntactically valid and idempotent.
- TypeScript definitions mirror SQL tables with zero type errors.
