# Plan 02-02: Deterministic 4-State Dose Engine & Audit Emitter

## Objective
Implement the deterministic dose state machine ensuring reminders never automatically mark doses as taken and every state change is strictly audited.

## Tasks
1. Define the 4 dose states: `not_yet`, `taken`, `unsure`, `unconfirmed`.
2. Implement state machine transition validator (`src/services/dose-engine.ts`):
   - Prohibit automatic ingestion markings.
   - Enforce allowed transitions:
     - `not_yet` -> `taken` (confirmed ingestion)
     - `not_yet` -> `unsure` (elder confusion)
     - `not_yet` -> `unconfirmed` (scheduled window passed)
     - `unsure` -> `taken` (caregiver verified)
     - `unconfirmed` -> `taken` (late verified ingestion)
   - Reject illegal transitions with typed errors.
3. Integrate immutable audit logging for all dose mutations (`src/services/audit-service.ts`).

## Acceptance Criteria
- Dose engine strictly blocks illegal transitions.
- Automatic reminder delivery cannot mark doses as `taken`.
- Audit logs capture actor, previous state, new state, and timestamp.
